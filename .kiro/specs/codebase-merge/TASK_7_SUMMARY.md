## Technical Implementation Details

### Reporting Architecture

The reporting system uses a three-layer architecture:

1. **Data Layer** (`reports.py`):
   - `SalesReports` class with PostgreSQL-optimized queries
   - `PurchaseReports` class (placeholder for future implementation)
   - `ReportingService` class for high-level dashboard aggregation

2. **API Layer** (`views_admin.py`):
   - `AdminReportingViewSet` with REST API endpoints
   - Date parsing and validation
   - Query parameter handling
   - Permission enforcement (admin-only access)

3. **URL Layer** (`urls_admin_vendor.py`):
   - Router registration for RESTful endpoints
   - Automatic URL pattern generation

### Database Optimization

All sales reports use raw SQL with:
- `GROUP BY` for aggregation
- `SUM()` for revenue totals
- `AVG()` for averages
- `COUNT(DISTINCT)` for unique counts
- Proper JOINs for related data
- Date filtering at database level

### Security

- All endpoints require JWT authentication
- `IsAdminUserRole` permission class enforces admin-only access
- Only confirmed orders are included in reports

### API Features

- Date range filtering via query parameters
- Configurable result limits
- Top-N queries for dashboards
- JSON response format
- Decimal-to-float conversion for JSON serialization
